# Roadmap

**Scope: everything self-serve before launch.** Every item below (all of roadmap items PR3–PR7) ships before launch, so a board member can change anything without a developer ([ADR 0002](adr/0002-product-principles.md)). Each item gets a contract in `docs/contracts/` before work starts; product choices are made by the user/board.

**GitHub tickets track active work.** This page summarizes scope and dependencies; link each new task to its ticket instead of maintaining competing execution updates. Existing delivered-item summaries remain historical context. ADRs record decisions and stay unchanged when work ships ([ADR 0001](adr/0001-record-architecture-decisions.md), [ADR 0029](adr/0029-tracked-work-and-zero-spend.md)).

Current ownership/shared-UI/games work: [epic #109](https://github.com/SGU-MSA/sgu-msa-site-private-history/issues/109). Organization safety and the $0 setup walkthrough: [#110](https://github.com/SGU-MSA/sgu-msa-site-private-history/issues/110). The old repository retains the private tracker; the clean public code repository and release readiness are tracked in [#118](https://github.com/SGU-MSA/sgu-msa-site-private-history/issues/118). Games start with Brothers/Sisters and must support host-editable team names/grouping ([#113](https://github.com/SGU-MSA/sgu-msa-site-private-history/issues/113)); this decision does not change the website People groups.

Item IDs (PR3, PR4, …) are roadmap items, not GitHub pull request numbers.

Developer tooling: shared MCP verification and project-local private connections are tracked in [#122](https://github.com/SGU-MSA/sgu-msa-site-private-history/issues/122); configuration ownership follows [ADR 0030](adr/0030-project-local-mcp-additions.md). This work does not change the application release scope.

Both tracks branch from `integration` and run in parallel ([ADR 0016](adr/0016-integration-branch-and-release-pr.md)).

## Dependencies

- Track A items stack only where one needs another: the data providers come first, then roadmap item PR3, whose permissions and activity log every later dashboard item uses. Roadmap items PR4–PR7 follow in order unless a contract shows an item does not depend on the one before it.
- Track B is independent of Track A: D1 → PR2 → PR8.

When an item ships, update its Status here (`Planned`, `In progress`, `Done`), the board steps in the [Board Handbook](../handover/SGU-MSA-Website-Handbook.docx), and the [architecture diagrams](architecture.md).
